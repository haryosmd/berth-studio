> **Важно:** Berth Studio на ранней стадии разработки. Приложение для macOS уже можно [скачать](https://github.com/haryosmd/berth-studio/releases/latest), оно работает с PostgreSQL и MongoDB. Кликабельный прототип показывает, куда движется проект.

## Зачем нужен Berth Studio?

Если вы пишете бэкенд, ваш день наверняка выглядит примерно так:

- DBeaver открыт для базы данных;
- Postman открыт для API;
- рядом заметка со строками подключения для dev, staging и prod.

Berth Studio собирает всё это в одном окне и при этом очень бережно обращается с продакшеном.

## Что умеет Berth Studio

- **Базы данных:** PostgreSQL, MongoDB, Supabase и Firebase. Можно смотреть таблицы, редактировать строки, выполнять запросы и читать документы.
- **dev, staging и prod:**
  - У одного подключения есть по одному профилю на каждое окружение, и у каждого профиля свой хост и свои учётные данные.
  - Окружения команда называет сама (local, qa, prod-eu и так далее), а вкладку можно закрепить за своим окружением и сравнивать два окружения рядом.
  - Если подключения в текущем окружении нет, Berth Studio прямо об этом скажет, а не будет угадывать.
- **Отдельные базы для чтения и записи:**
  - В профиле можно указать основной сервер (primary) и реплики для чтения (read replicas).
  - Чтение автоматически уходит на реплику, а запись всегда остаётся на основном сервере.
  - Можно и вручную закрепить запрос за одним из них, а профиль только с репликами для чтения просто не может писать.
- **API Collections:** Запросы лежат в папках любой вложенности, как дерево файлов в VS Code. Есть импорт из Postman, Insomnia, OpenAPI, HAR, Bruno и cURL.
- **ERD:** Можно строить диаграммы по реальной схеме базы или свободно набрасывать новые таблицы.
- **Страховка:**
  - Продакшен открывается только для чтения.
  - Любое изменение в таблице сначала показывает свой SQL и только потом выполняется.
  - Чтобы записать что-то в прод, сначала нужно ввести имя подключения.
- **Секреты:** Пароли и токены хранятся в системной связке ключей. Они никогда не попадают в файлы рабочего пространства и не показываются в интерфейсе.
- **Обновления:** Когда выходит новая версия, справа вверху появляется значок. Обновление скачивается в один клик, и приложение устанавливает его, только если подпись подлинная.

## Попробовать

### Скачать приложение (macOS)

Возьмите свежий `.dmg` на [странице релизов](https://github.com/haryosmd/berth-studio/releases/latest). Одна сборка работает и на Apple silicon, и на Intel. Откройте `.dmg` и перетащите Berth Studio в «Программы».

Приложение пока не подписано Apple Developer ID, поэтому macOS блокирует первый запуск. Откройте **Системные настройки → Конфиденциальность и безопасность**, прокрутите вниз и нажмите **Всё равно открыть**. Следующие версии приходят через встроенный механизм обновлений, который ставит обновление, только если его подпись проходит проверку.

### Запустить из исходников (macOS)

Понадобятся Rust (через `rustup`), Node.js 20 или новее и Xcode Command Line Tools. Первая сборка занимает несколько минут. Вторая команда запускает временный PostgreSQL с демо-данными на `127.0.0.1:54329` (пользователь `app`, пароль `berth-dev-app`; `scripts/dev-db/stop.sh` удаляет его). Для MongoDB установите `mongodb-community@8.0` из Homebrew и запустите `scripts/dev-db/mongo-start.sh`: временный набор реплик на `127.0.0.1:54330` (пользователь `app`, пароль `berth-dev-app`, база аутентификации `events`).

```bash
npm ci
scripts/dev-db/start.sh
npm run tauri dev
```

### Подключиться к базе в облаке

Управляемые базы вроде Amazon RDS и Aurora, Azure Database, Google Cloud SQL или DigitalOcean подписывают серверные сертификаты собственным CA провайдера, которому macOS по умолчанию не доверяет. Berth Studio всё равно проверяет сертификат.

**Amazon RDS и Aurora работают сразу.** Berth Studio поставляется с [корневыми сертификатами RDS](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.SSL.html) и доверяет им только для хостов под `rds.amazonaws.com` и `rds.amazonaws.com.cn`, так что поле **CA certificate** оставьте пустым. Если Amazon добавит корень, которого эта версия ещё не знает, тест подключения об этом скажет, а бандл вашего региона в этом поле выручит до следующего релиза.

Для других провайдеров и для сервера с самоподписанным сертификатом тест подключения падает с `invalid peer certificate: UnknownIssuer`, пока вы не передадите Berth Studio его CA:

1. Скачайте сертификат CA (файл `.pem`) у провайдера. Обычно он лежит на странице подключения к базе и называется «CA certificate», «root certificate» или «SSL certificate»:
   - **Azure Database for PostgreSQL:** корневые сертификаты из [документации по TLS](https://learn.microsoft.com/azure/postgresql/flexible-server/concepts-networking-ssl-tls).
   - **Google Cloud SQL:** серверный CA на странице **Connections** инстанса, см. [документацию](https://cloud.google.com/sql/docs/postgres/configure-ssl-instance).
   - **DigitalOcean:** сертификат CA на странице **Overview** базы, см. [документацию](https://docs.digitalocean.com/products/databases/postgresql/how-to/connect/).
   - **Самоподписанный сервер:** сертификат CA, который его подписал, от того, кто этим сервером управляет.
2. В форме подключения PostgreSQL укажите путь к файлу в поле **CA certificate** профиля нужного окружения. Путь может начинаться с `~`.
3. Нажмите **Test**. Файл читается при каждом подключении, так что не переносите его.

Файл CA дополняет системное хранилище доверия, а не заменяет его. Базам на вашей машине и базам с выключенным TLS он не нужен.

### Открыть прототип

Прототип — это один HTML-файл с демо-данными. К настоящим базам данных он не подключается.

```bash
open design/prototype.html
```

В Windows или Linux просто откройте файл двойным щелчком.

Что стоит попробовать:

1. **Профиль отсутствует:** переключите окружение на **dev** в верхней панели. `events-db` станет серым, потому что у него нет профиля для dev.
2. **Куда идёт запрос:** откройте **Query editor** и нажмите на чип `acme-db · dev · auto → read`, чтобы увидеть, где выполнится запрос.
3. **Папки:** наведите курсор на папку в **API Collections** и нажмите **+**, чтобы добавить запрос или папку.
4. **Импорт:** нажмите **⇧⌘I** и попробуйте импортировать пример.
5. **Быстрый переход:** нажмите **⌘K**, чтобы перейти куда угодно.

### Запустить тесты

Нужен Node.js 20 или новее. Больше ничего устанавливать не нужно.

```bash
npm test
```
